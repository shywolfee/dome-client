# Contributing

Run `npm run lint` and `npm test` before committing. Coverage must remain at or above 80%.

## Commit messages

Use a concise, imperative subject in the conventional format `<type>(<scope>): <summary>`, followed by a blank line and a body when the change needs context. The body should explain the user-visible effect, important implementation choices, and validation or migration notes. Keep the subject specific and avoid vague messages such as `update stuff` or `fix things`.
